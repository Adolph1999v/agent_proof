# Improvement Changelog

This document connects every meaningful experiment to evidence and the next engineering decision. Results will use the same cases and resources for the baseline and final workflow unless a difference is explicitly documented.

| Stage | What we tried and why | Evidence | Decision / learning |
| --- | --- | --- | --- |
| Problem selection | Compared API migration, accessibility repair, bug reproduction, and independent patch verification against user value, reproducibility, and hackathon fit. | Public reports show coding agents can weaken tests or overstate validation; AgentProof also supports authentic public patch benchmarks. | Selected independent verification and retained ContractFix as a separate project. |
| Phase 1 | Created a minimal local web application with isolated dependencies and automated quality gates. | Ruff and TypeScript checks passed; 3 backend and 2 frontend tests passed; the production build and live frontend-to-backend proxy check succeeded. | Establish a clean, reproducible base before implementing verification behavior. |
| Phase 2 | Added deterministic patch intake for clean pytest repositories: disposable cloning, protected test/config snapshots, patch preflight, bounded baseline execution, and local JSON reports. | Automated verifier cases cover a valid source-only patch, modified tests, an invalid patch, a failing baseline, a dirty source checkout, and API report retrieval. | Existing tests can establish regression evidence, but a passing baseline remains `INCONCLUSIVE` until independent challenge tests exist. |
| Phase 2 hardening | Replayed the browser-pasted manual case after terminal-newline normalization and compared its evidence with a no-op variant. | Regression tests now reject patches with no observable repository effect and continuously validate a complete Git-generated manual fixture. | Patch syntax and a passing baseline are insufficient when the candidate changes nothing; official demos must use complete generated diffs rather than reconstructed hunks. |
| Phase 2 fixture replay | Ran the official README patch through AgentProof itself. The patch applied, but the baseline suite exposed that its fixture test read the patched working file. | The fixture test now reconstructs its base from the immutable `HEAD` blob, and the complete quality gate passes. | Verification tests must derive baseline inputs from the recorded source commit, never from candidate-modified working files. |
| Phase 2.5 | Replaced patch-first intake with natural-language automatic discovery backed by stable project identities and approved snapshots. | Integration cases cover isolated repositories, Git and non-Git path moves, copied-identity rejection, stale approvals, parent history, change kinds, incompatible Git lineages, corrupted objects, cross-project manifest tampering, current-state audits, and automatic verification. | Exact patches remain internal evidence; the normal user workflow is project path → task → inspect → approve or verify. Every stored object is scoped by repository identity. |
| Phase 2.5 baseline replay | Rescanned an unchanged approved project, then introduced a normal product change without supplying a patch. | A dedicated frontend regression test covers exact baseline equality; the approved snapshot comparison must discover this commit's changed and added files automatically. | Exact equality is now reported as `Matches approved baseline`; any later difference is discovered from project state rather than user-authored patch text. |
| Phase 3 | Added a localhost-only, one-request-at-a-time model adapter that proposes structured invariants and one pytest challenge, followed by static safety validation and separate baseline/candidate execution. | Scripted cases prove `VERIFIED`, `UNSAFE`, task-binding, blocked-capability behavior, untracked-file reporting, and exclusion of existing and candidate-added test source from model context. A live Qwen3.6 27B Q6 smoke run generated a whitespace challenge that failed on the baseline and passed on the candidate (409 prompt + 645 completion tokens; 37,369 ms); the hardened replay produced the same test and verdict. | Keep the model outside the verdict boundary. Treat the live result as integration evidence only; run the pinned multi-model, multi-case bake-off before selecting a production model. |
| Baseline | Defined as existing tests run against the candidate patch without AgentProof's frozen-test comparison or preserved evidence. | To be measured on authentic public cases in Phase 5. | Freeze the same repository, patch, and test budget for baseline and AgentProof evaluation. |
