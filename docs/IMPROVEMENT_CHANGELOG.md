# Improvement Changelog

This document is a chronological record of meaningful experiments, failures, evidence, and engineering
decisions. Older rows describe their exact checkpoint, so their test counts and open work are not the
current project status. The final measured result is the current submission result.

| Stage | What we tried and why | Evidence | Decision / learning |
| --- | --- | --- | --- |
| Problem selection | Compared API migration, accessibility repair, bug reproduction, and independent patch verification against user value, reproducibility, and hackathon fit. | Public reports show coding agents can weaken tests or overstate validation; AgentProof also supports authentic public patch benchmarks. | Selected independent verification and retained ContractFix as a separate project. |
| Phase 1 | Created a minimal local web application with isolated dependencies and automated quality gates. | Ruff and TypeScript checks passed; 3 backend and 2 frontend tests passed; the production build and live frontend-to-backend proxy check succeeded. | Establish a clean, reproducible base before implementing verification behavior. |
| Phase 2 | Added deterministic patch intake for clean pytest repositories: disposable cloning, protected test/config snapshots, patch preflight, bounded baseline execution, and local JSON reports. | Automated verifier cases cover a valid source-only patch, modified tests, an invalid patch, a failing baseline, a dirty source checkout, and API report retrieval. | Existing tests can establish regression evidence, but a passing baseline remains `INCONCLUSIVE` until independent challenge tests exist. |
| Phase 2 hardening | Replayed the browser-pasted manual case after terminal-newline normalization and compared its evidence with a no-op variant. | Regression tests now reject patches with no observable repository effect and continuously validate a complete Git-generated manual fixture. | Patch syntax and a passing baseline are insufficient when the candidate changes nothing; official demos must use complete generated diffs rather than reconstructed hunks. |
| Phase 2 fixture replay | Ran the official README patch through AgentProof itself. The patch first exposed candidate-modified fixture input; a later post-commit replay exposed that even `HEAD:README.md` was a moving dependency. | The evaluation now pins the patch's exact base README beside the patch, and the complete gate passes both before and after commit. | Evaluation fixtures must be self-contained and immutable; they cannot depend on working files or the product repository's moving `HEAD`. |
| Phase 2.5 | Replaced patch-first intake with natural-language automatic discovery backed by stable project identities and approved snapshots. | Integration cases cover isolated repositories, Git and non-Git path moves, copied-identity rejection, stale approvals, parent history, change kinds, incompatible Git lineages, corrupted objects, cross-project manifest tampering, current-state audits, and automatic verification. | Exact patches remain internal evidence; the normal user workflow is project path → task → inspect → approve or verify. Every stored object is scoped by repository identity. |
| Phase 2.5 baseline replay | Rescanned an unchanged approved project, then introduced a normal product change without supplying a patch. | A dedicated frontend regression test covers exact baseline equality; the approved snapshot comparison must discover this commit's changed and added files automatically. | Exact equality is now reported as `Matches approved baseline`; any later difference is discovered from project state rather than user-authored patch text. |
| Phase 3 | Added a localhost-only, one-request-at-a-time model adapter that proposes structured invariants and one pytest challenge, followed by static safety validation and separate baseline/candidate execution. | Scripted cases prove `VERIFIED`, `UNSAFE`, task-binding, blocked-capability behavior, untracked-file reporting, and exclusion of existing and candidate-added test source from model context. A live Qwen3.6 27B Q6 smoke run generated a whitespace challenge that failed on the baseline and passed on the candidate (409 prompt + 645 completion tokens; 37,369 ms); the hardened replay produced the same test and verdict. | Keep the model outside the verdict boundary. Treat the live result as integration evidence only; run the pinned multi-model, multi-case bake-off before selecting a production model. |
| Phase 3 full-project replay | Asked Qwen3.6 27B Q6 to challenge 20 AgentProof changes using the vague task `add new features`. | LM Studio processed 14,734 prompt tokens, used the remaining 1,650 tokens for reasoning, reached the 16,384-token limit after 204,266 ms, and returned empty final content. The failure is recorded in `traces/runtime/phase3-full-project-context-limit.json`. | Rank Python application changes, cap every file and total context, reserve 3,072 output tokens, show elapsed UI time, preserve failed trajectories, and keep detected changes visible until a verified state is explicitly approved. |
| Phase 3 reliability bounds | Reduced the context and reasoning budget after a full-project run consumed its entire 3,072-token completion allowance without returning challenge JSON. | Deterministic tests cover task/file/prompt caps, relevance ordering, `/no_think`, the 512-token output budget, the 120-second default timeout, timeout reporting, and lock release; live runtime remains to be measured. | Send at most four task-relevant Python files in an 18,000-character prompt, fail clearly within the default two-minute budget, preserve failure evidence, and run a pinned LM Studio replay before claiming a speed improvement. |
| Phase 3 timeout diagnosis | Inspected the failed trajectory and LM Studio server log after a tiny smoke prompt timed out at 120 seconds. | The server generated roughly 754 private reasoning tokens before starting JSON because `/no_think` was placed in the system message; the client disconnected mid-response. A separate hard-coded alias also differed from the loaded model ID. | Put `/no_think` at the end of the user prompt, cap output at 512 tokens, use a 16K model context, auto-discover the sole loaded generation model, and fail clearly when zero or multiple candidates are loaded. |
| Phase 3 demo model selection | Replayed the bounded smoke case with Qwen3.6 27B Q6 in LM Studio and Qwen2.5-Coder 7B Q4 in Ollama. | The current Qwen3.6 runtime ignored both prompt and request-level non-thinking controls and spent all 512 tokens on reasoning. Qwen2.5-Coder returned a valid 125-token challenge in 28,478 ms; it failed on the baseline, passed on the candidate, and produced `VERIFIED`. | Use Qwen2.5-Coder 7B as the reproducible submission demo default. Keep Qwen3.6 in the later model bake-off rather than hiding its recorded incompatibility or increasing demo timeouts. |
| Phase 3 protected-input replay | Verified AgentProof's own Phase 3 implementation, which correctly included new regression tests and configuration/version changes. | The original all-or-nothing policy returned `UNSAFE` before execution. A final UI replay then showed that excluding candidate-touched test paths allowed a deleted regression test to escape the deterministic stage. | Quarantine candidate test/config changes, generate an exact application-only patch, and run every frozen approved pytest module—including original versions of modified or deleted tests. Candidate tests never create a pass. |
| Project picker | Replaced path-only project selection with a localhost-backed, click-driven directory browser while retaining manual entry. | Focused backend and frontend cases cover home defaults, path validation, inaccessible children, navigation, selection, recovery, and keyboard dismissal. | Browsing remains shallow and read-only; selecting a folder does not trust it or run code until the user explicitly starts inspection. |
| Before/After review | Added a read-only UI view of approved and current file contents so a person can see the change before verification. | Automated cases cover added, modified, deleted, and binary files. Browser replays confirmed both prepared demo projects and line-level highlighting. Previews are limited to 12 files and 20,000 bytes per version. | Use approved snapshot objects as the Before source and verified current files as the After source. Highlight changed lines, but do not expose binary contents or claim that a preview is a verdict. |
| First full evaluation | Compared a green-test baseline with AgentProof on five correct and five unsafe controlled patches using the same repositories, tasks, patches, pytest command, and local model budget. | The first recorded run scored 60% for the baseline and 70% for AgentProof. Rejected trajectories exposed malformed JSON, missing imports, incorrect literals, and behavior-mode mistakes. | Do not hide inconclusive runs or tune case IDs. Add workflow-wide import validation, bounded evidence-guided repair, explicit preservation intent, and support for `pytest.raises` as valid evidence. |
| Evidence-guided challenge repair | Added at most two repair attempts after the initial proposal. Each retry receives the exact validation or baseline/candidate execution failure; every attempt remains in the trajectory and all tokens/time are aggregated. | Regression tests cover invalid syntax, missing application imports, undefined names, safe support-import repair, incorrect expectations, preservation-mode correction, repeat workspace execution, and exception assertions. A browser replay repaired the model's missing `date` import and returned `VERIFIED` with baseline failed/candidate passed. | Keep repair bounded and deterministic. AgentProof may add only an unambiguous missing `pytest` or allowed standard-library import already present in changed source; executed evidence still owns the verdict. |
| Final UI real-case replay | Ran the public-derived dateutil empty-input fix and the adversarial deleted-test change through the actual browser workflow. | The public case became `VERIFIED` after the generated invariant failed on baseline and passed on candidate. The deleted-test case became `UNSAFE` because its frozen original odd-number test ran and failed; a dedicated backend regression now locks this globally. | Use both UI paths in the video: one correct change requiring independent evidence, and one deceptively green unsafe change blocked without trusting its deleted test. |
| Final measured evaluation | Re-ran six correct and five unsafe patches, including a dependency-free behavioral reproduction derived from python-dateutil issue #78. | `evaluation/results/recorded-evaluation.json`: baseline 63.6% overall and 20% unsafe detection; AgentProof 100% overall, 100% unsafe detection, and 100% correct-patch acceptance. Total time 32,938 ms; 9,467 prompt + 1,600 completion tokens; no paid model service. | Use this 11-case result as the scoped submission claim. State clearly that it is hackathon-scale evidence, not universal correctness, and retain a larger public-corpus/model bake-off as future work. |
| Baseline | Existing tests run against the complete candidate patch, including candidate-authored test/config changes, without frozen evidence or an independent challenge. | On the pinned 11 cases it accepted four of five unsafe patches and scored 63.6% overall. | The baseline is reproducible and intentionally realistic: “tests are green” is useful, but it is not independent proof when the patch can alter the tests that judge it. |
| Relocation replay | Rebuilt setup from tracked files in temporary folders, including one with spaces. | `make setup` installed Python 3.12.13, 29 pinned Python packages, and frontend packages; `make check` passed 82 backend and 13 frontend tests, lint, type checks, and build. Both copied demos were selectable and passed current-state audits. A live model challenge was not run. | Keep Python launchers local to each copy and quote Makefile paths. Generated evidence, caches, environments, builds, and model files are not submission inputs. |
